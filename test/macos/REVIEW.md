# Adversarial review: launchd recovery and private reports

## Findings corrected

- A malformed or unrelated legacy plist could block starting a healthy canonical
  service, and reinstall could stop the service before detecting the legacy
  problem. Unrecognized files are preserved, known job labels are inspected
  independently, and read failures are checked before stopping.
- A rejected bootstrap could leave a newly written plist despite no registered
  job, making later commands believe a supervisor existed. Failed installation
  now checks registration: restore/remove the definition only when absence is
  proven; preserve it when registered or uncertain.
- Native fixture guards assumed a GUI domain existed. They now accept the
  specific missing-domain result while preserving permission errors.
- The old support transport adds account context and uses authenticated HTTP.
  The new report command uses a separate typed schema and private endpoint,
  without authentication, mirror fallback, raw log text or telemetry.
- A capability GET could itself expose an IP to an unverified proxy. Both CLI
  upload and server acceptance default to disabled until infrastructure is
  checked. The default CLI never sends even the GET.
- Unix file modes do not establish Windows privacy. Report files now receive
  a protected current-user DACL from creation on Windows, before any bytes are
  written; an ACL check uses the same file handle.

## Evidence

- Mac mini: real launchd and CLI lifecycle fixtures passed with the race detector,
  including repeated install/start/stop, disabled jobs, legacy migration,
  KeepAlive recovery, bad configuration and uninstall. Canonical and legacy
  registrations were absent after cleanup.
- A separate real helper waiting 12 seconds after SIGTERM showed that bootout
  returns immediately; the proposed command-timeout bug was not reproduced.
  Existing waiting logic observes the process afterward. No speculative timeout
  change was made.
- Linux full Go suite with race detector passed. Report tests also ran natively
  on the Mac. Windows code and its ACL tests cross-compiled; native Windows ACL
  execution remains unverified.
- Report tests cover cancellation, EOF, double consent, unchanged preview bytes,
  private fields mixed into recognized/unknown logs, rotation and size limits,
  symlinks/FIFOs, arbitrary versions, redirects, proxies and endpoint gating.
- A report generated by the actual CLI passed the backend strict schema and a
  mocked POST delivery. No real support email or report was sent.

## Limits

The launchd failure is reproduced and covered; this does not prove the cause of
every crash experienced by the original reporter. Unknown log text and desktop
memory-only logs are intentionally omitted. An agent UUID is a stable,
correlatable identifier. Deployed CDN/proxy/application IP retention has not been
verified, so upload remains disabled and no release or deployment was performed.
